## Offline behaviour and consent

Both the historical `EventSyncService.logEvent` callers and direct `logAnalyticsEvent` calls submit immediately to Firebase's native SDK. The SDK owns normal offline capture, native session/time and durable uploading after connectivity returns. JavaScript connectivity flags are not acknowledgements. An SDK promise resolving means request acceptance, not confirmed ingestion.

Only SDK rejections use the app's sanitised retry store, and only if `getAppInstanceId` indicates analytics storage is permitted. A null/failed consent check does not start a second collection channel. Legacy Realm retries are snapshotted, serialised, sanitised on replay and removed only after acceptance; old acknowledged records are pruned. The content-country/language reset retains the queue. Capture timing, original session and historical country/user-property context for old queued records cannot be recovered. Exclude unattributable legacy retries from exact country/profile totals. Clearing old client properties does not erase historical server-side data; retention/deletion policy needs separate authorised administration. New fallback retries include captured_at_ms for custom analysis, but GA4 still dates them at SDK ingestion; this is not a supported event backdating API.

The SDK also honours its native collection/consent settings. No new opt-in policy is inferred from accepting terms, and no legally complete consent UI has been invented. The app currently lacks a common caregiver analytics opt-out screen; the product/privacy owner must define jurisdiction-specific consent/retention policy. Advertising storage/user-data/personalisation and advertising IDs are disabled by default; iOS Meta tracking requires ATT grant and revocation disables it. Android Meta advertising-ID collection stays disabled until an explicit product consent flow exists.

Tests verify SDK invocation offline/online/unknown connectivity, privacy filtering, rejected transport, denied consent, legacy persistence/serial replay, no live-results skipping, initial/repeated route handling and restore separation. **No final-branch native offline/restart/reconnection event was reconciled in DebugView or BigQuery.** Browser access ended before DebugView. Do not present unit doubles as delivery proof.

## Required delivery reconciliation

For each signed Android/iOS flavour, record app ID/project ID/version and consent state (without tokens). Enable Analytics debug mode only on a test installation: Android `adb shell setprop debug.firebase.analytics.app <application-id>`; iOS launch argument `-FIRDebugEnabled`. Use that project's DebugView.

1. Online: open first screen, create one caregiver-entered profile, edit it, view two advice screens, search once, save/share content and run one tool. Reconcile expected source calls and the actual native events, accounting for documented legacy aliases.
2. Disable network. Repeat a different journey, background/foreground, force stop/restart, then reconnect. Confirm eligible native events, original timestamps/session behaviour and no private values. Test denied analytics storage and collection disabled separately: no application retry should bypass them.
3. Restore two profiles twice. Expect two restore operations, restored_count 2 each, no profile_created or onboarding-count events caused by restore.
4. Exercise failed saves, failed URL opening, cancelled share, cancelled restore, killed imports and malformed files. Confirm they do not produce success events. Test local/remote notification delivery vs actual taps independently.
5. Disable debug mode afterwards (`adb shell setprop debug.firebase.analytics.app .none.` / remove iOS argument). Debug events do not establish standard production export completeness; inspect non-debug test journeys in the authorised GA4/BigQuery pipeline separately.

GA4 has consent, transport, storage, session, retention, installation identity and processing limitations. No app/SDK promise can guarantee lossless exact-once totals. Concurrent process failure between SDK acceptance and app-outbox deletion can duplicate a retry. A caregiver can reinstall or restore on a second device. Profile totals must come from a defined authoritative, privacy-reviewed data model/ledger; GA4 profile-creation estimates and current-selected-child properties cannot reconstruct an exact census. No such backend ledger was added in this RN upgrade.

Reference: [Firebase Android collection controls](https://firebase.google.com/docs/analytics/android/configure-data-collection), [Apple controls](https://firebase.google.com/docs/analytics/ios/configure-data-collection), [DebugView](https://firebase.google.com/docs/analytics/debugview).
