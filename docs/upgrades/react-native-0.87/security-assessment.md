# Application security and resilience assessment

This is a repository/source assessment with targeted tests and available read-only crash history. It is not a penetration-test certificate, a full Maven/Pods CVE scan or confirmation of production configuration. npm audit results do not cover Gradle, native binaries, signing systems or backend services.

## Prioritised findings

| Severity | Evidence and disposition | Verification / remaining work |
| --- | --- | --- |
| High, build hosts | Gradle 9.4.1 falls in three October 2026 advisories: repository TLS-error fallback and unauthenticated/deserialisation channels on the local build host. Upgrade wrapper distribution to 9.8.1 with its first-party SHA256. | Advisory ranges and fixed version verified from Gradle maintainers; checksum agrees between services.gradle.org and the official GitHub distribution asset digest. RN build-plugin compiler 2.2.0 initially failed on embedded Kotlin 2.4 metadata. A scoped build-compiler 2.4.21 patch passes configuration and native WebView Kotlin compilation while the resolved application KGP remains 2.2.10. Full final Android builds must still pass on 9.8.1. Local-channel attacks require co-location, not remote access to the installed mobile app. |
| High, residual backup protection | Exports historically use app-embedded keys, fixed IV and unauthenticated CBC. New exports have random IV + HMAC and reject tampering before decrypting. | Node crypto regressions pass; real native round-trip still required. Embedded shared key remains extractable from a distributed client; use a separately designed passphrase/user-held-key migration for stronger confidentiality/authenticity. Legacy readers cannot authenticate old files. |
| Medium, confirmed consent bug | iOS code enabled advertiser tracking in the ATT denied path and repeated initialisation. | Replace with one guarded configuration path. Denied/blocked/unavailable never enable tracking; granted then revoked disables it. Default advertising-ID collection is false in all ten iOS app plists and ten Android branded manifests. Android does not infer consent. Five regressions cover the decision paths. Meta automatic generic app events are still a separate product/privacy-policy consideration. |
| Medium, telemetry disclosure | Raw search text, selected-child health/sex/age attributes and arbitrary error strings could leave the device. | Central allowlist drops free text/clinical data/identifiers; clear legacy child user properties; manual nonfatal reports retain error class/stack frames with a generic message and scrubbed breadcrumbs. Backup UI no longer logs raw Realm errors. Automatic native/JS fatal SDK reports still require a privacy review against actual production payloads; this wrapper cannot sanitise third-party native logs. |
| Medium, imported data safety | Invalid nested collections/duplicate IDs/query syntax in imported child UUIDs; raw controls silently removed inside JSON text. | Reject incompatible records before opening live writes; strip only historical outer framing. Confirmation explicitly explains replacement. Real historical/device fixtures remain required. |
| Medium, URI handoff | Server-supplied survey/feedback links opened without awaiting errors and were counted as submissions. | Restrict those handoffs to HTTP(S)/mailto, reject control/script/file/intent URLs, handle native errors and count only opening. HTTP links are retained for compatibility; CMS should migrate them to HTTPS. |
| Medium, iOS network policy — open | All ten current app plists allow arbitrary ATS loads, with a localhost exception. | Production environment files/live media endpoints are unavailable here. Do not remove the broad exception and claim every country's media still works without a TLS/content inventory. Release action: validate production API/media hosts over HTTPS, then narrow ATS and retain development-localhost needs separately. Android release cleartext defaults are stricter; debug allows local HTTP. |
| Medium, symbol/configuration coverage | Checked-in iOS RNFB core/symbol phases are attached to Bebbo but not all app targets. | Explicit static Firebase privacy/screen settings in every plist; all ten archive schemes invoke the CocoaPods uploader with the archived app's own GoogleService plist/dSYMs. Unsigned fixture builds skip upload. Actual signed symbol receipt remains unverified. Private Hermes map generation added; do not publish maps containing environment values. |
| Low, build/test dependencies | deepmerge 4.3.1 prototype-poisoning advisory remains through CLI/Jest/SVGR. | No published compatible patch found; do not downgrade CLI/Jest to audit-suggested obsolete majors. Config/build exposure, not evidence of remote exploitation in the mobile bundle. Monitor upstream. |

No confirmed critical-severity finding was established. Residual items above must not be hidden by the npm zero-high snapshot.

## Other reviewed surfaces

- **Secrets:** tracked-file high-confidence scan found no private-key, GitHub-token, AWS access-key or OpenAI-key patterns. Only the standard debug keystore is tracked. Production environment files, signing credentials and Firebase service configuration are ignored/external. This did not scan all Git history or prove credentials were never exposed; native Firebase client API keys are identifiers requiring service restrictions, not substitutes for server credentials. Production key restrictions/rotation and GitHub secret-scanning configuration need authorised console access.
- **Storage:** user Realm remains schema 4/Realm 20.2.0; it is not converted to encrypted Realm in this framework migration. OS app sandbox protects ordinary access; rooted/unlocked device and backup threat models remain. Android app backup is disabled in the shared manifest. Local JSON exports are encrypted, private temporary copies are cleaned on normal exits, and hard-kill cache remnants remain a device/recovery check. Photos/preferences are not a complete portable backup.
- **Authentication:** Drive uses the reviewed native authorisation path and account-scoped access. No app-wide caregiver login/backend credential flow was found in this branch. Live token expiry/revocation/account switching and server access rules were not tested. Do not reuse a mobile client secret as backend authorisation.
- **WebViews/content:** shared HTML screens now retain source/bridge props. Vimeo still needs its JavaScript iframe/bridge and broad origin handling for generated HTML; removing JavaScript/blanket origin restrictions would break content. Sanitising CMS-provided HTML and an explicit navigation/media allowlist need a known publisher/endpoint inventory, rather than silently disabling embeds. No backend CMS XSS assessment was performed.
- **Deep links:** existing reviewed parser validates supported routes/parameters, rejects malformed/stale links and tests navigation recovery. Android exported launcher/deep-link activities are intentional entry points; signing into an external service is not authorised merely by a URL. Country native link declarations are retained and require actual association/domain checks.
- **Permissions:** camera/gallery, notifications, boot reception and legacy pre-Android-13 storage requirements are retained. Both Android exact-alarm permissions are present; store-policy eligibility, denied permission fallback and OEM alarm limits require release/device review. Removing them without testing clinical reminders could disrupt existing scheduling. Historical legacy 500-alarm crashes do not prove the new provider is immune.
- **AI:** this branch's ChatBot/SupportChat is a scripted FAQ tree. No hosted LLM/RAG provider key or separate pilot backend was found in those files. The different ReraiChatbot branch, server guardrails, rate limits and model safety controls were not reviewed here.
- **Workflows:** external Actions are pinned to full resolved commits; read-only repository permissions, locked installs, checksum-pinned bundletool, unsigned fixture guards and no deployment/store-publishing jobs. Untrusted PRs do not receive release secrets in these workflows. Pinning is not proof every upstream action/dependency is vulnerability-free. A full build-attestation/dependency-verification rollout was not added speculatively.

## Native/dependency decisions

RN 0.87 remains an active release line per the [official release overview](https://reactnative.dev/releases/overview). Keep 0.87.1/React 19.2.3 and tested peer libraries for this branch; do not combine another RN major with this stabilisation. Android SDK 37/AGP 9.2.1/Kotlin 2.2.10/NDK 27.1 and iOS 15.1 app targets remain. The legacy tvOS target is not claimed as supported/tested.

The installed RN Firebase 26.4.1 declares Android Firebase BOM 34.18.0 and Apple SDK 12.19.3; the committed pod lock resolves Core 12.19.3 and Analytics/Crashlytics/Messaging 12.19.0. Apple's 12.19.3 contains the backported eMudhra trust-store security fix; Firebase 27/Apple 13/SPM is not needed merely to obtain that patch. No Firestore native app module was added. Firebase 12 is the final CocoaPods major, so the SPM migration needs a planned follow-up across all targets, not indefinite deferral.

Realm 20.2.0 is intentionally pinned to avoid a simultaneous database migration; real old-file migration/offline tests remain a release gate. dotenv 3.4.12 retains tested FLAVOR behaviour; major 5 requires its own country-environment regression proof. Reanimated/Worklets/Skia/Victory and the other native UI libraries retain the earlier tested versions. ESLint 8 is deprecated tooling and a planned lint-config migration, not justification to force an incompatible linter into this framework upgrade. No complete native-transitive vulnerability scan was available; do not infer zero native CVEs from these checks.
